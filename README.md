# 拾光

> 面向全厂网络与信息化工作的个人工作台
> React 19 · TypeScript · Vite · Tailwind CSS v4 · Electron

## 当前能力

- 今日工作台：集中显示今日已完成、待办、注意事项和当前电脑的同步通道状态
- 收件箱：独立单行快速录入，回车即可进入“收到工作”；完整新增继续负责项目、类型和截止时间等结构化字段
- 工作事项：统一管理任务、服务请求、故障、变更和巡检
- 故障快线：故障可从“收到工作”直接进入“正在干的”，自动保留“先恢复业务、处置后补分类”的审计语义，不新增主状态
- 事项编辑：可修改类型、优先级、项目、负责人、下一步与注意标记，不破坏来源和文件关联
- 信息化项目：项目与工作事项关联，完成度按事项有效进度的算术平均值计算并展示口径
- 设备资产：登记网络设备、服务器、终端和系统台账
- 文件盘：按收到、分类、正在干、干完、归档五层展示任务及其对应文件
- 文件待归属区：允许先登记文件线索元数据；未绑定任务前禁止物化、下载或进入正式五层文件组
- 文件驻留：明确区分仅元数据、受管缓存、离线副本和本地工作副本，显示逻辑文件 ID
- 工作统计：仅统计当前工作台真实数据，不展示演示指标
- 五层工作流：收到工作、分类工作、正在干的、干完的、归档的
- AI 状态整理：只接受后端受限接口返回的候选分类，不把建议伪装成已完成
- 设置：独立且可操作的 AI、COS 与本地底座接入入口；密钥只在 Windows 原生安全提示中输入
- 同步诊断：显示远端 Head、版本、拉取/提交时间、状态代码和冲突版本，冲突时阻断覆盖
- 移动交互：底部主导航、更多功能抽屉、全屏搜索、44px 触控目标、横向阶段滑动和底部表单

## 数据原则

- COS 是业务文件与状态的唯一持久化真源
- 应用状态为 `paw.shiguang.state.v2`；旧 v1 仅在首次远端接管时迁移
- 拾光不直连 COS，不持有 COS 或 CAM 凭据
- AI 与 COS 均只通过 NodeGateway。renderer 只处理 endpoint/model 与 bucket/region；模型 API Key、SecretId、SecretKey 不进入网页界面、IPC payload、日志、业务状态或 COS
- Electron 只保留界面偏好；业务状态不写浏览器持久化，也不创建额外业务缓存
- NodeGateway 是唯一允许的业务缓存与同步出口；后台定时拉取只在本地无未提交变更时更新
- 多远端 head 或删除提案状态会阻断提交，不做自动覆盖
- 五个文件组共用逻辑文件 ID；跨组只修改清单并记录事件，不复制 COS Blob
- 本地固定入口为 `D:\拾光工作盘`（D 盘卷标“文件盘”）
- 文件线索可以暂不绑定任务，但此时只允许保存元数据；进入正式文件组、物化、下载或同步 Blob 前必须绑定具体任务
- 项目代码只引用 Git 提交；普通工作文件由 NodeGateway 按需物化到任务目录
- 未接入的外部来源、附件上传、SLA 和 AI 指标不会伪装成可用

## 工作流口径

### 收件箱与故障快线

- 快速录入只要求标题，默认写入 `RECEIVED`，类型为“任务”、来源为“快速录入”、下一步为“待分类”。
- 完整新增用于填写事项类型、项目、负责人、优先级、截止日期和说明，两者不是同一个入口。
- 标准流程仍为 `RECEIVED → TRIAGED → IN_PROGRESS → COMPLETED → ARCHIVED`。
- 只有“故障”允许使用应急快线 `RECEIVED → IN_PROGRESS`。快线会增加 `流程:故障快线` 标签和“重点关注”标记，处置完成后仍需补齐分类和证据。

### 项目完成度

```text
事项有效进度 = COMPLETED/ARCHIVED ? 100 : clamp(completionProgress, 0, 100)
项目完成度 = round(Σ 项目内事项有效进度 ÷ 项目内事项数)
无事项项目 = 0%
```

完成度对项目内全部事项等权，不按文件数或更新时间加权。执行中的事项可在“编辑事项”中以 5% 为步长维护有效进度；工作统计使用同一函数，避免不同页面出现两套口径。

### 文件归属

- “待归属文件线索”只保存名称、分类、标签等元数据，不占用本地文件正文空间。
- 补充任务归属后，文件线索进入该任务当前阶段的文件组，并随任务换组。
- 只有 NodeGateway 可以按需物化文件；renderer 不建立第二套正文缓存。

## 三端同步定义

“三端”固定指家庭电脑、办公电脑和 C·ONE。三端是独立节点，各自拥有身份、NodeGateway/Edge、状态和受管缓存；节点之间不直连，只分别通过出站 HTTPS 与 COS 交换获准的加密不可变版本。

“已同步”必须同时有相应节点的版本头、摘要和签名验证证据。本机在线只代表本机通道状态，不能代替办公端或 C·ONE 状态；无法在本机验证的节点必须显示“本机未验证”。COS 是唯一持久化真源，但不运行 Agent、不调度任务、不持有锁。

## 目录结构

```text
src/
  components/
    layout/        # 侧栏与全局搜索
    modals/        # 新增与编辑事项弹窗
    ui/            # LiquidModal、LiquidSelect、页面过渡
  context/         # 工作台状态与 NodeGateway 同步状态
  lib/             # 状态合同、同步控制器、工作台语义和测试
  pages/           # 八个工作台页面
  index.css        # Liquid Glass 设计系统和响应式布局
electron/          # 主进程、预加载与六接口安全桥
```

## NodeGateway 安全接入

```text
React renderer → preload 固定 IPC → Electron main → 127.0.0.1 NodeGateway → PAW/COS
```

主进程继续使用既有六条 Shiguang 路由，renderer 只获得实时状态、拉取状态和提交状态三个高层能力。生产启动通过固定 DPAPI helper 读取令牌，并在全局 README 门禁通过后处理业务请求。C·ONE 只读取拾光的 DailyBrief 视图；现有功能与四个任务零修改，也没有扩展或绕过 NodeGateway 契约。

设置页的接入配置走另一条固定本机安全控制链：

```text
renderer 非秘密字段 → 固定 IPC schema → Windows 安全配置器 → NodeGateway 配置
                              └─ API Key / SecretId / SecretKey 仅在原生凭据提示中输入
```

AI API Key 使用 DPAPI CurrentUser 保存；COS 继续使用 NodeGateway 既有受限 `cos.env`。配置器只返回脱敏状态，不创建通用代理，不静默安装计划任务，也不会自动发送 AI 测试请求。
